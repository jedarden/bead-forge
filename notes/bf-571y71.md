## Root cause

`Storage::add_label` (`src/storage/sqlite.rs:1304`) trims the label and **rejects
empty-after-trim** labels — i.e. whitespace-only labels (`" "`, `"\t"`, `"\n"`, …)
are rejected. This is correct, intentional behavior and matches the bead's own
"Test label trimming whitespace" acceptance criterion.

The 4 failing tests asserted the **opposite** — that whitespace-only labels are
*accepted* and stored as distinct labels. The tests had wrong expectations; the
production code was right. The retry agent never caught this because it didn't
actually run the suite (it falsely blamed OpenSSL).

## Fix applied

Corrected the 4 test expectations to assert the real contract (whitespace-only
labels are rejected; nothing is stored). Test-assertion changes only — **no
production code touched**. All **31/31 tests now pass**.

This brings bf-66k24a's acceptance criterion ("All tests pass") to genuinely met.

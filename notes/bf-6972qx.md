## Technical Details

### Dual Storage Strategy
Labels are stored in two tables for compatibility:
- `labels` table: br (beads_rust) compatibility layer
- `bead_labels` table: bead-forge specific table with foreign key constraints

### Transaction Safety
All label operations use `with_immediate_transaction()` ensuring atomicity:
- Bead creation and label insertion happen atomically
- Bead updates and label changes happen atomically
- Individual add/remove operations are atomic

### Foreign Key Constraints
The `bead_labels` table has proper foreign key constraints:
```sql
CREATE TABLE IF NOT EXISTS bead_labels (
    bead_id TEXT NOT NULL REFERENCES issues(id) ON DELETE CASCADE,
    label    TEXT NOT NULL,
    PRIMARY KEY (bead_id, label)
);
```

This ensures:
- Labels are automatically deleted when beads are deleted (CASCADE)
- Each bead-label combination is unique (PRIMARY KEY)
- Only valid bead IDs can be inserted (FOREIGN KEY)

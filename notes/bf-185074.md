## Notes

The implementation uses a thread-based timeout approach which is the standard pattern for process timeouts in Rust, as `std::process::Child` does not have a built-in timeout method. The implementation correctly:
- Spawns cargo test in a separate thread
- Monitors for timeout with periodic checks
- Kills the process tree (including child processes) on timeout
- Captures and returns all output produced before timeout

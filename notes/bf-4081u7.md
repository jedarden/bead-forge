# bf-4081u7 — Audit closure: removed root test scripts covered by tests/*.rs

Parent: bf-3o9. Verifies (does not assume) that the 22 root-level files removed in
commit `8dc4a79` ("chore(bf-3o9): remove orphaned root-level test shell scripts and
committed test_version binary, scenarios covered under tests") are genuinely covered
by `tests/*.rs`.

## Method

Read-only audit. Confirmed deletions via `git ls-files` (all 22 gone from tracking
AND working tree) and `git show --stat 8dc4a79` (each listed as a deletion). Then
fanned out one reader per scenario category to open the cited test files and confirm
the scenario is actually exercised (test function names + assertion quotes), not
assumed from filenames. Cross-checked flagged gaps against `src/` to judge whether
they test behavior the tool actually has.

## Result

All 6 categories map to >=1 real `tests/*.rs` that genuinely exercises the scenario.
The coverage claim in 8dc4a79 **HOLDS**. No category is genuinely uncovered, so no
port was required. No working-tree code changes (read-only).

- `test_invalid_type.rs` omits empty-string / numeric / unicode-emoji type strings and
  a `TASK`->`task` case-folding assertion (`src/model.rs:221` does apply `to_lowercase`).
  `list --type <custom>` filtering is covered elsewhere (test_invalid_query_json_output,
  test_error_json_schema_validation, epic_cli_label_sort_filter).
- No CLI test creates an epic via `--type epic --priority 0` (model layer + non-epic CLI
  priority tests cover it); CLI invalid-priority rejection is asserted only on `list`.
- Epic implementation/closure is covered only at the library layer (epic_comprehensive.rs);
  `verify_epic_implementation.rs` is mis-named (tests type serialization, not completeness).
- No rust test inspects the `export_hashes` table directly (behavioral equivalent via
  `doctor::check` / `count_unflushed`).

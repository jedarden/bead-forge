# Bead bf-4494od: Trace File Naming and Location Verification

## Summary

Verified that trace file naming and location conventions are properly implemented in bead-forge.

## Acceptance Criteria Verification

### ✓ Trace files use bf- prefix convention
- All 352 trace directories in `.beads/traces/` use `bf-` prefix
- `TraceManager::list_bead_traces()` filters for `bf-` and `needle-` prefixes
- Verification example confirms all directories follow the convention

### ✓ Files are created in .beads/traces/ directory
- `TraceManager::new()` constructs paths as `base_dir/.beads/traces/`
- `TraceManager::ensure_traces_dir()` creates directory with proper error handling
- All trace operations use this standardized location

### ✓ Naming follows established patterns (e.g., bf-* with unique identifier)
- `unique_bead_trace_dir()` generates names: `{bead_id}-{timestamp}`
- Timestamp format: `YYYYMMDD-HHMMSS-3f` (millisecond precision)
- Counter suffix (`-{counter}`) added if timestamp collision occurs
- Example: `bf-naming-test-4494od-20260724-184308-310`

### ✓ Multiple test runs create distinct trace files
- Each call to `unique_bead_trace_dir()` creates a new unique directory
- Test `test_multiple_runs_create_distinct_traces()` verifies this behavior
- Timestamp-based naming ensures temporal separation

## Implementation Details

The implementation is in `src/trace.rs`:

- `TraceManager` struct manages all trace operations
- `unique_bead_trace_dir()` method creates uniquely named directories
- `run_cargo_test_to_bead_trace()` writes structured traces
- Each trace contains: `metadata.json`, `stdout.txt`, `stderr.txt`

## Timing Recording (Dependency)

Timing information is already implemented in `TraceMetadata`:
- `start_time: Option<String>` - RFC3339 format
- `end_time: Option<String>` - RFC3339 format  
- `duration_ms: Option<u64>` - Duration in milliseconds
